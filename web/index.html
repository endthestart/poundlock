Linux installation guide

Install the node first. It reports the machine’s hardware and connections, and keeps it awake during work. You can set up a model server afterward.

Before you start

  • Linux with systemd and glibc 2.36 or newer, such as Debian 12, Ubuntu 24.04 or current CachyOS. Check with systemctl --version and getconf GNU_LIBC_VERSION.
  • An Intel/AMD x86_64 or ARM64 processor. Check with uname -m.
  • A non-root login with sudo, Bash, coreutils, util-linux, systemd-logind and polkit.
  • The machine must be able to reach the controller URL below. Drivers and models are needed for inference, but are not required to enroll.

Install and connect

  1. In Enroll a machine, enter a unique name, choose Linux and select the processor. Choose System routing, or One interface to restrict its connection to the controller.
  2. Download all three files into one folder on the Linux computer, such as ~/Downloads/poundlock. If using this page on another computer, copy the files to Linux first. Any folder you own works.
  3. Create a token when ready to install. Open a terminal in that folder, run the displayed install command, and paste the token at the hidden prompt. Tokens expire after 15 minutes and can be used once.
  4. The installer checks the binary and configuration, places them in their permanent locations, and starts a systemd service under your login. Sudo installs the service; the node runs without root privileges. Keep the installer for later diagnostics, upgrades and removal.
  5. Confirm Online in Machines and review Technical details. Use Model server setup help for installation links matched to the reported OS and GPU, or connect a server you already run. Save its endpoint on Connections, then add a model on Models using this machine. Choose Ollama — managed loading and unloading for Ollama, or always-ready for an externally managed server.
  6. Use Test on Models to confirm inference, then submit a small job with a verification command. If the machine can sleep, configure Wake-on-LAN below and test from real sleep. Avoid SSH probes during the test; they can wake some machines.
Installed files and advanced configuration

The installer creates /etc/poundlock/node.toml, a private /var/lib/poundlock directory, poundlock-node.service, and a polkit rule allowing the service login to inhibit sleep. You do not need to place downloads in system folders.

Drivers, models, model services, routes and firewall rules stay under your control. The default always-ready runtime assumes your model server is already running.

For One interface, run these commands in the download folder (use the ARM64 filename on ARM). Copy an interface name into the form and download the updated configuration.

chmod +x ./poundlock-linux-x86_64
./poundlock-linux-x86_64 node-interfaces

Advanced runtime commands in node.toml use absolute executable paths, without shell strings. Writable state must fit /var/lib/poundlock, or a narrow systemd ReadWritePaths override. Keep passwords and API keys out of node.toml; the node stores its credential separately with mode 0600.

Diagnose or recover

From the folder containing the installer, run:

sudo bash ./poundlock-node.sh doctor
journalctl -u poundlock-node.service --since '10 minutes ago'

Doctor checks configuration, the selected connection, authentication and sleep inhibition without running models.

  • Configuration error: correct node.toml and run /var/lib/poundlock/poundlock node-check --config /etc/poundlock/node.toml.
  • Connection error: confirm the service is running and can reach the controller. One interface will stay offline if that interface disconnects.
  • Plain HTTP refused: use an https:// controller address, or add allow_insecure_http = true to node.toml to accept plain HTTP on a network you trust.
  • Authentication error after a reinstall: remove the old registration in Machines, create a new token and enroll again. Finish or cancel active work first.
  • Sleep inhibition denied: check systemd-logind, polkit and /etc/polkit-1/rules.d/60-poundlock-node.rules. Run doctor under the service account; do not disable sleep system-wide.
  • Interrupted install: correct the reported problem and repeat the command. An existing managed installation keeps its credential. The installer refuses unmanaged paths and symlinks.
Upgrade and roll back

In Enroll a machine, select Linux and your processor, then download the node binary and Linux installer. Downloading the binary displays the complete upgrade command with its checksum. Run it from that download folder; keep your existing configuration and enrollment. No new token is needed.

sudo bash ./poundlock-node.sh upgrade --binary ./poundlock-linux-x86_64 --sha256 HASH
sudo bash ./poundlock-node.sh rollback
sudo bash ./poundlock-node.sh resume

Upgrade pauses an idle node, validates the replacement and keeps the previous binary. Active work blocks maintenance. Rollback restores the previous binary; resume recovers an interrupted maintenance operation after its cause is fixed. Check Test on Models afterward.

Configurations without auto_update keep automatic idle updates; set auto_update = false in node.toml to choose explicit upgrades. A node that verifies signed updates installs only a newer binary signed with its release key; any other node refuses automatic updates unless the controller address is https:// or loopback.

Remove or reinstall

To uninstall from a working Linux machine, finish or cancel its work, then run:

sudo bash ./poundlock-node.sh remove

This revokes its credential and removes the service, configuration, node binaries and polkit rule. Restore controller connectivity first if it is unreachable. Model files and GPU drivers remain installed.

For a computer already wiped or no longer available, use Remove machine in its card. This disconnects the registration and keeps job history; it cannot uninstall files remotely. A new token cannot take over a name that is still online or paused; wait until it is offline, or remove it first. A new installation requires a new enrollment token.

Check the complete installation
  • Confirm Online, the selected connection, Test on Models and a small verified job.
  • Reboot and confirm reconnection without another token prompt.
  • Test sleep, wake, inference and cancellation when supported.
  • Upgrade, roll back, remove and enroll again. Report any unclear step or unexplained failure.
